# vergoboy.ir / stream — پخش‌کننده‌ی ویدیوی هم‌زمان (Watch Party)

پلیر ویدیوی مدرن و کامل، با قابلیت تماشای هم‌زمان و سینک‌شده‌ی چند نفر، برای
`vergoboy.ir/stream`.

## امکانات
- یک «اتاق تماشای مشترک» برای همه‌ی بازدیدکننده‌ها — پخش/مکث/سرعت/جابه‌جایی‌زمان
  برای همه‌ی کاربران یکسان و سینک می‌شود (با درایفت‌کرکشن خودکار).
- شناسایی کاربران فقط با وارد کردن اسم (بدون رمز)، و نمایش نوتیفیکیشن لحظه‌ای
  «فلانی پلی/پاز/سیک کرد، فلانی وارد/خارج شد و ...» برای همه.
- پلی‌لیست مشترک با افزودن ویدیو از طریق آپلود فایل یا لینک مستقیم/HLS.
- پشتیبانی از چند زیرنویس روی هر ویدیو (vtt یا srt — تبدیل خودکار srt به vtt)
  با پنل کامل شخصی‌سازی استایل (فونت، اندازه، رنگ متن و پس‌زمینه، شفافیت،
  دورخط، ضخامت، فاصله از پایین صفحه) — این تنظیمات فقط محلی است و روی نمایش
  بقیه اثر ندارد.
- پشتیبانی از چند «کانال صدا / دوبله» روی هر ویدیو (فایل صوتی جدا که به‌صورت
  خودکار با ویدیو سینک می‌شود) — انتخاب کانال صدا هم محلی و مستقل برای هر
  کاربر است (هرکس می‌تواند زبان دوبله‌ی خودش را انتخاب کند درحالی‌که زمان
  پخش برای همه یکی‌ست).
- دکمه‌های کامل کنترل: پخش/مکث، ۱۰ ثانیه جلو/عقب، آیتم بعدی/قبلی، صدا،
  سرعت پخش (۰.۵x تا ۲x)، تمام‌صفحه، Picture-in-Picture.
- پنل «استریم خارجی»: ساخت کلید استریم و نمایش آدرس Push (برای OBS یا اپ
  موبایل) و آدرس Playback (HLS) بر اساس سرور RTMP موجودِ خودت، یا وارد کردن
  دستی یک آدرس HLS برای افزودن به پلی‌لیست.
- هویت بصری کاملاً مطابق با vergoboy.ir (رنگ، فونت، هدر/فوتر یکسان).

## ساختار پروژه
```
/opt/stream/
├── app.py                  # اپ اصلی Flask + Socket.IO
├── config.py                # تنظیمات (env-driven)
├── state.py                  # وضعیت مشترک اتاق تماشا
├── srt_to_vtt.py              # تبدیل‌کننده‌ی زیرنویس
├── requirements.txt
├── templates/index.html
├── static/
│   ├── css/style.css
│   ├── js/app.js
│   └── js/vendor/{hls.min.js, socket.io.min.js}   # لوکال، بدون CDN خارجی
├── media/{uploads,subs}/      # فایل‌های آپلودشده
├── data/state.json            # ماندگاری پلی‌لیست بین ری‌استارت‌ها
└── deploy/
    ├── vergoboy-stream.service
    └── nginx-stream.conf
```

## نصب روی سرور

```bash
# ۱) کپی پروژه
sudo mkdir -p /opt/stream
sudo cp -r ./* /opt/stream/
cd /opt/stream

# ۲) ساخت virtualenv و نصب وابستگی‌ها
python3 -m venv venv
./venv/bin/pip install -r requirements.txt

# ۳) مالکیت فایل‌ها برای کاربر سرویس (www-data یا هر یوزری که Nginx/سرویس‌های دیگه‌ت استفاده می‌کنن)
sudo chown -R www-data:www-data /opt/stream
```

### فونت‌ها
صفحه از همان فونت‌های لوکال سایت اصلی استفاده می‌کند و مستقیماً به مسیر
`/register/static/fonts/...` ارجاع می‌دهد (در `static/css/style.css`). چون
هر دو اپ روی یک دامنه‌ هستند، نیازی به کپی‌کردن فایل‌های فونت نیست — فقط مطمئن
شو اپ اصلی (که `/register` را serve می‌کند) در حال اجراست.

## تنظیمات (Environment Variables)
همه‌ی این‌ها در `config.py` مقدار پیش‌فرض دارند و می‌توان در یونیت systemd
override کرد:

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `STREAM_HOST` | `127.0.0.1` | هاست لوکال برای bind |
| `STREAM_PORT` | `8801` | پورت لوکال |
| `STREAM_SECRET_KEY` | — | حتماً عوضش کن |
| `STREAM_MAX_UPLOAD_MB` | `8192` | حداکثر حجم آپلود فایل ویدیو (مگابایت) |
| `STREAM_RTMP_PUSH_TEMPLATE` | `rtmp://vergoboy.ir:1935/live/{key}` | الگوی آدرس Push برای استریم خارجی |
| `STREAM_HLS_PLAYBACK_TEMPLATE` | `https://vergoboy.ir/hls/{key}/index.m3u8` | الگوی آدرس HLS برای پخش استریم زنده |

**نکته‌ی مهم درباره‌ی استریم خارجی:** این دو قالب آخر باید با ساختار واقعی
سرور RTMP/HLS که از قبل روی سرورت نصب و در حال اجراست هم‌خوانی داشته باشد.
این اپ فقط یک کلید تصادفی می‌سازد و این دو رشته را با `{key}` پر می‌کند —
خودش هیچ سرور RTMP/HLS اجرا نمی‌کند. اگه ساختار مسیرهای سرور موجودت فرق
دارد (مثلاً پورت یا اسم اپلیکیشن RTMP فرق دارد)، این دو env var را در فایل
سرویس systemd مطابق آن تغییر بده.

## راه‌اندازی با systemd

```bash
sudo cp /opt/stream/deploy/vergoboy-stream.service /etc/systemd/system/
sudo nano /etc/systemd/system/vergoboy-stream.service   # SECRET_KEY و الگوهای RTMP/HLS رو تنظیم کن
sudo systemctl daemon-reload
sudo systemctl enable --now vergoboy-stream
sudo systemctl status vergoboy-stream
```

لاگ‌ها: `journalctl -u vergoboy-stream -f`

## راه‌اندازی Nginx
محتوای `deploy/nginx-stream.conf` را داخل بلاک `server` موجود سایتت (همان
که `vergoboy.ir` و `/register` و `/donate` را سرو می‌کند) اضافه کن، سپس:

```bash
sudo nginx -t && sudo systemctl reload nginx
```

نکات کلیدی این کانفیگ:
- یک `location /stream/` که هم صفحه/API و هم WebSocket (مسیر
  `/stream/socket.io/`) را به پورت لوکال ۸۸۰۱ پروکسی می‌کند (با هدرهای
  `Upgrade`/`Connection` لازم برای WebSocket).
- یک `location /stream/media/` که فایل‌های ویدیوی آپلودشده را مستقیماً از
  دیسک serve می‌کند (سریع‌تر از عبور از Flask و با پشتیبانی صحیح از
  Range requests که برای جابه‌جایی داخل ویدیو لازم است).
- `client_max_body_size` برای اجازه‌ی آپلود فایل‌های بزرگ.

## تست لوکال (بدون Nginx)
```bash
cd /opt/stream
STREAM_PORT=8801 ./venv/bin/python3 app.py
# سپس مرورگر: http://127.0.0.1:8801/stream/
```

## نکات طراحی / محدودیت‌ها
- **یک اتاق برای همه:** طبق درخواست، فقط یک اتاق مشترک وجود دارد؛ همه‌ی
  بازدیدکننده‌ها در همان اتاق هستند.
- **سینک:** سرور موقعیت/وضعیت پخش را نگه می‌دارد؛ هر اقدام کنترلی (پخش، مکث،
  سیک، تغییر سرعت، انتخاب آیتم) به همه‌ی کلاینت‌ها broadcast می‌شود و هر
  کلاینت هر ۶ ثانیه هم به‌صورت خودکار موقعیت خودش را با سرور می‌سنجد و در
  صورت اختلاف بیش از ۱.۲ ثانیه خودش را تصحیح می‌کند.
- **زیرنویس و کانال صدا محلی هستند:** انتخاب این‌ها sync نمی‌شود تا هرکس
  بتواند زبان زیرنویس/دوبله‌ی خودش را مستقل از بقیه انتخاب کند، درحالی‌که
  زمان پخش برای همه یکسان می‌ماند. فقط *وجود* زیرنویس/کانال صدای جدید (وقتی
  کسی اضافه‌اش می‌کند) با نوتیفیکیشن به همه اطلاع داده می‌شود.
- **کانال صدا:** به‌خاطر محدودیت پشتیبانی مرورگرها از سوییچ صدای چندکاناله‌ی
  داخل یک فایل ویدیویی واحد، روش استفاده‌شده اینه که هر «دوبله» یک فایل صوتی
  جداست که به‌صورت خودکار با video sync می‌شود (چنگش‌زمانی هر ۲ ثانیه چک
  می‌شود). این روش روی همه‌ی مرورگرها به‌طور یکسان کار می‌کند.
- **فرمت ویدیو:** فقط فرمت‌هایی که مرورگر می‌تواند مستقیم پخش کند (mp4, webm,
  ogg, mov) قابل آپلود/پخش هستند؛ mkv/avi و مشابه پشتیبانی نمی‌شوند (نیاز به
  ترانس‌کود دارند که خارج از scope این پروژه است).
- **پایداری پلی‌لیست:** پلی‌لیست و موقعیت پخش در `data/state.json` ذخیره
  می‌شود؛ بعد از ری‌استارت سرویس، پلی‌لیست باقی می‌ماند (وضعیت play/pause
  بعد از ری‌استارت همیشه pause است).
